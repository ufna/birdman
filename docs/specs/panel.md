# Спека: админ-панель

> Первоклассный продукт, не приложение к API: красивая админка мониторинга и статистики, главный скриншот OSS-анонса. Трек П0–П2.

## 1. Принципы

1. **Строго клиент публичного API**: OpenAPI + SSE (`/v1/events/stream`); если панели нужны данные — сначала эндпоинт, потом экран. Никаких приватных лазеек.
2. **Встраивается в master** (`go:embed` собранной статики): self-host получает панель бесплатно, «два бинаря + Postgres» остаётся правдой. Отдаётся с `/` того же listener'а :443.
3. Метрики-графики — из VictoriaMetrics **через master-proxy** (`GET /v1/metrics/query?...` → VM), чтобы панель не знала про топологию мониторинга.
4. Тёмная + светлая тема с первого экрана; live-обновления без F5 (SSE), таблицы переживают reconnect.
5. Auth: логин по admin API-ключу → HttpOnly session cookie; роли из скоупов ключа (readonly видит всё, кнопки скрыты). **«Admin-ключом» — это рекомендация, а не проверка (tracker #990):** `POST /v1/session` не требует скоупа вовсе и наследует ключ ЦЕЛИКОМ, включая привязку к (project, env). Сессия, заведённая ПРИВЯЗАННЫМ ключом, живёт под теми же гейтами, что и он: «readonly видит всё» верно только для непривязанного ключа, а на сырых проксиях (`/v1/logs/query`, `/v1/metrics/query` · `/query_range`) его запрос СУЖАЕТСЯ его парой (tracker #994, `master.md` §6): 200, но видно только своё. Практически: экран «Логи» показывает логи своего проекта и НЕ показывает историю, записанную до проектной разметки стримов (решение «дожить ретенцией»); из графиков метрик работают собранные на `birdman_servers`, а построенные на агентских (пер-серверных) и платформенных сериях приходят пустыми — пары в них нет. 403 на этих ручках остался ровно для одного случая: пара привязки непригодна к сужению (fail-closed).

   **Сессия сообщает привязку, и панель на неё опирается (tracker #1000).** `POST/GET /v1/session` отдают additive-поле `binding: {project, env}` — есть только у привязанного ключа (`master.md` §6). Панель хранит его в `SessionInfo` и делает ровно три вещи:
   - **честно называет причину 403.** Источник — `useBindingRefusal()` (`lib/session.tsx`): привязан ключ → `ui.err.boundKey` («Запрос отклонён: ключ привязан к {project}/{env}…»), не привязан → `undefined`, и каждая поверхность подставляет СВОЙ прежний текст (`ErrorNote`/`MetricMessage` — `ui.err.forbidden` про readonly, `ConfirmDialog` — `confirm.err.forbidden` про права на действие). Общий запасной текст был бы новой ложью: действию нужен deploy/admin, а не readonly. До #1000 обе поверхности показывали свой текст про права ОБОИМ, то есть привязанному readonly-ключу панель называла несуществующую проблему — локализованный, но ложный диагноз. Текст говорит про КЛЮЧ, а не «логи вам недоступны»: серверное сужение (#994) вернёт привязанному оператору его собственные данные, и формулировка обязана это пережить;
   - **не ретраит неретраибельное.** `useQueryRange` (`lib/useMetrics.ts`) на 403 гасит 15-секундный поллинг; `useInstantQuery` запоминает ЗАПРОС, на котором пришёл 403, и не повторяет его по смене `refetchKey` (в Stats это `generated_at` из `/v1/stats/overview`, а он перечитывается по всплеску SSE с дебансом 3с — то есть чаще поллинга). Смена самого запроса поллинг возвращает: гасится таймер, а не хук. Прочие ошибки поллятся как раньше (они транзиентны). Цена вопроса — не rate-limit (nginx панели даёт 30 r/s при burst 60, пять графиков в 15с — это 0.33 r/s), а бессмысленный трафик и поток 403 в логах мастера;
   - **ничего не прячет по признаку привязки.** Ни пункт «Логи» в навигации, ни графики: гейтить видимость привязкой значило бы отобрать у привязанного оператора его СОБСТВЕННЫЕ данные после #994. Видимость по-прежнему гейтит только СКОУП — пункты навигации в `Shell.tsx` (`adminOnly`) и admin-роуты в `App.tsx` (`canAdmin`). Пустая выдача (истории логов старше проектной разметки привязанный ключ не увидит — решение «дожить ретенцией», #994) — это НЕ отказ, и панель показывает её обычным пустым состоянием.

   **Чего #1000 НЕ закрыл** (замерено, не предположено): статус `forbidden` поднимается, только пока у графика ещё нет данных — у графика с данными 403 гасит поллинг молча, старые точки остаются без пометки; карточка fill-rate на «Статистике» рисует `stats.ttm.trueUnavailable` («metrics proxy unavailable») на любом не-`ok`, то есть привязанному ключу называет недоступность ПРОКСИ вместо причины в ключе; `PromoteDialog`/деплой-ошибки в `screens/Deploys.tsx` печатают сырой `detail` мастера (тот же класс, что #996, но другая поверхность — tracker #1005).
6. **Интернационализация (уточнено в v0):** UI двуязычный — EN (каноничный, для OSS-анонса) + RU, **100% покрытие: ни одной захардкоженной user-facing строки** (правило держит guard-тест `no-hardcoded.test.ts`). Автоопределение при первом заходе (`navigator.languages` начинается с `ru` → RU, иначе **EN по умолчанию**), ручной выбор в `localStorage` переживает перезагрузку и больше не перебивается автоопределением. Бренд и API-токены (semver, id, сырые коды) не переводятся, но их **человекочитаемые подписи переводятся** — состояния (`state.*`), виды событий ленты (`event.*`, сырой код остаётся в `title` бейджа), скоупы ключа (`scope.*`).

   **Тело ошибки апстрима — не текст для пользователя (tracker #996).** `ApiError.message` это `${code}: ${detail}`, где `detail` — свободная английская проза мастера или VictoriaMetrics; подставленная в UI, она обходит каталог и делает интерфейс двуязычным только наполовину. Различать надо КОД и `detail`: код показывать можно (без него у оператора не остаётся ничего для баг-репорта), `detail` — нельзя. Графики метрик приведены к этому первыми: `useQueryRange` (`lib/useMetrics.ts`) держит в состоянии не сообщение, а `errorCode: string | null` (`MetricErrorCode`), и текст выбирает `MetricMessage` из каталога: `metric.err.expired` на `unauthorized` (401 — единственный код, где действие оператора отличается: войти заново), `metric.err.offline` на `null` (запрос не дошёл вовсе), `metric.error` с `{code}` на всё прочее.

   Держат это ДВА слоя, и оба нужны. Первый: **у двух апстримов разная форма ошибки**, и поле `error` значит в них разное — у master это код (`{"error":"internal","detail":"…"}`), у VM/Prometheus это ПРОЗА, а код лежит в `errorType` (`{"status":"error","errorType":"422","error":"cannot parse query: …"}`). Живая VM отвечает на отвергнутый запрос не 200, а 422/400/503, master проксирует её тело вербатим (`httpapi/ops.go`), поэтому конверт VM в `lib/metrics.ts` разбирается ДО общей ветки `!res.ok` — иначе проза читается как код. Там же 502/504 уходят в мягкую ветку ДО разбора JSON: шлюз отдаёт HTML, и `JSON.parse` бросал раньше проверки статуса. Второй слой: **санитайзер `errorCodeOf`** клампит код до формы токена (`/^[a-z][a-z0-9_]{0,39}$/`, иначе `http_<status>`). Тип `string | null` сам по себе не уже прежнего `string` — прозу в него можно положить, и компилятор смолчит; гарантию даёт одна проверяемая точка на границе состояния, а не дисциплина каждого вызывающего.

   Остальные поверхности того же класса (`ErrorNote` на не-403, `screens/Deploys.tsx`, `loginErrorMessage`, `Fleet.tsx` на payload события, админские `e.detail ?? e.code`) ещё печатают `detail` — tracker #1005. Учтите при их разборе: guard-тест `no-hardcoded.test.ts` ищет только КИРИЛЛИЦУ, то есть от захардкоженной АНГЛИЙСКОЙ строки и от прозы апстрима автоматической защиты нет вовсе — только ревью и тесты поверхности.

## 2. Стек

React 18 + TypeScript + Vite; клиент API генерируется из `openapi.yaml` (`openapi-typescript`); графики — uPlot (лёгкий, real-time); таблицы — TanStack Table; стили — Tailwind + Radix-примитивы. Дизайн-токены (палитра/типографика) — отдельный файл, готовим к работе дизайнера (2–3 недели, до OSS-анонса обязательно).

(Уточнено в v0.) Клиент API пока написан руками и типизирован вручную (`panel/src/lib/api.ts` + SSE-подписчик `sse.ts` с реконнектом по `after_id`) — `openapi.yaml` ещё не существует; при его появлении клиент переводится на генерацию. Дизайн-токены — `panel/src/styles/tokens.css` (бренд-палитра, обе темы). Сборка панели встраивается в master: `panel/build.sh` → `master/internal/panelui/static` (go:embed), node на хосте не обязателен (docker-фолбэк), без сборки master отдаёт placeholder.

(Уточнено в v0.) **i18n-слой** — свой лёгкий, без внешних либ: `panel/src/lib/i18n.tsx` (провайдер + хук `useT()` с `t(key, params?)` и plural-вариантом `tp(base, count)` на `Intl.PluralRules`; хук `useFormat()` — локале-зависимые длительность/относительное время/дата). Словари `panel/src/lib/locales/en.ts` (источник истины, `MessageKey = keyof typeof en`) и `ru.ts` (`Record<MessageKey, string>` — паритет ключей гарантируется компилятором + тестом: совпадение множеств ключей, отсутствие пустых значений, совпадение `{плейсхолдеров}`). **100% покрытие**: все пользовательские строки экранов/компонентов идут через `t()/tp()` — включая подписи состояний (`state.*`), видов событий ленты (`event.*` для всех kind из `store/*.go`; лента показывает подпись, сырой код — в `title`; неизвестный kind → сам код) и скоупов ключа (`scope.*`, показаны чипами в Shell). Единственный locale-слой вне каталога — `lib/format.ts` (единицы длительности/`… назад`, помечен `i18n-allow`). Технические `throw new Error(...)` вне провайдеров — по-английски (срабатывают до i18n). Формат чисел/дат/относительного времени локализован (`5s ago` / `5с назад`). Переключатель **EN/RU в Shell** рядом с темой/logout (компактный сегмент, `role=group` + `aria-pressed`). Дефолт EN, RU при `ru*`-локали; ручной выбор — `localStorage` (`birdman.lang`); ранний скрипт в `index.html` ставит `<html lang>` до первого рендера (без вспышки).

(Уточнено в v0.) **Поверхность зависимостей и `npm audit`.** Поверхность разделена надвое, и это разделение — не формальность, а то, что определяет реакцию на advisory. *Рантайм* (`dependencies`: react, radix, uplot, TanStack Table, @fontsource) собирается в `panel/dist` и через `go:embed` едет внутрь бинаря master до оператора — high здесь настоящая дырка в продукте. *Сборочные* (`devDependencies`: vite и её транзитивные postcss/nanoid, vitest, eslint, tsc) исполняются только в CI и на машине разработчика: их кода в собранной статике нет (проверяется grep'ом по `dist` — ноль вхождений), поэтому находка там — гигиена цепочки сборки, а не инцидент. Отсюда два шага в `.github/workflows/panel.yml`: `npm audit --omit=dev --audit-level=high` блокирует PR, полный `npm audit --audit-level=high` показывает warning и не блокирует — иначе релиз в чужом пакете останавливал бы несвязанную работу. Транзитивные дыры сборочных зависимостей чиним рефрешем лок-файла (`npm update <pkg>`), пока апстрим держит semver-совместимый патч; мажорный подъём vite или `overrides` — только если такого патча нет, потому что оба рискуют плагинным API (`@vitejs/plugin-react`, `@tailwindcss/vite`).

### П1 — операции (параллельно итерациям 4–5, ~2–3 недели) — ✅ реализовано (v0)

| Экран | Содержимое | Данные |
|---|---|---|

| **Деплои** | Таблица версий (semver, канал, состояние, дата), активная версия per регион, **прогресс pre-pull по тачкам**, кнопки Deploy / Rollback (с confirm), окно мультиверсий: сколько deprecated-дедиков ещё доигрывает | `/v1/versions`, `/v1/deploy`, `/v1/rollback`, SSE |

(Уточнено в v0.) Экраны **Деплои** (`/deploys`) и **События** (`/events`) добавлены в навигацию; детали дедика — дровер (Radix Dialog), открывается кликом на дедик во Флоте/Матчах и по ссылкам `srv …` в ленте. Всё — на существующем master API, новых эндпоинтов не добавляли.

- **Overview** (углублён реалтайм): живые счётчики (матчи/игроки/ready-буфер) обновляются по SSE плавно, без «прыжка» — `<LiveValue>` даёт короткую вспышку тона при изменении (ширина стабильна за счёт tabular-nums); индикатор свежести «обновлено N назад» (`ov.updated`, живая точка) по времени последнего успешного чтения (`useData.updatedAt` = максимум по источникам). Всё уважает `prefers-reduced-motion`.
- **Деплои**: таблица версий с цветными бейджами состояния (`toneOfVersionState`: registered/prepulling/active/deprecated/disabled); окно мультиверсий = active + deprecated и сколько дедиков каждой ещё живо (группировка `/v1/servers` по `version_id`, live-состояния); «активно по регионам» **выведено из живых дедиков** (`GET /v1/fleets` наружу не отдаётся — TODO в panel, per-region active_version недоступен точно); **прогресс pre-pull по тачкам** собран из событий `deploy_node_pulled` (множество спрогретых `node_id` + `remaining` из последнего события; total = спрогрето + remaining, либо оценка по живым нодам, пока событий нет), сидируется из `/v1/events` и обновляется по SSE (`deploy_started/node_pulled/activated/failed/rolled_back`); **Deploy/Rollback** — за confirm-диалогом Radix, `POST /v1/deploy` / `/v1/rollback`, кнопки скрыты у readonly-сессии (гейт `canDeploy` = скоуп deploy/admin из `GET /v1/session`).
- **Дедик-дровер**: отдельного `GET /v1/servers/{id}` в master нет → карточка ищет дедик в `/v1/servers` клиентом (логи/метрики работают и без строки, для reaped/failed); **таймлайн** — клиентский фильтр `/v1/events` по `server_id` (server-side фильтра нет — TODO) + live-дополнение из SSE; **логи** — сегмент **Live \| История** (`components/LogsPanel.tsx`, Логи v1): Live — байт-в-байт прежний live tail + скачивание файлом (`GET /v1/servers/{id}/logs?follow=&tail=`, chunked-стрим; download = тот же эндпоинт без follow → Blob; для reaped/failed — статус `gone`); История — поиск по VictoriaLogs через `GET /v1/logs/query` (`serverHistoryQuery`, `lib/logsql.ts`+`lib/logsHistory.ts`): диапазон **1ч/24ч/7д/14д** + текстовый фильтр (Enter/«Применить») + «показать ещё» постранично назад по времени (лимит страницы 500), **работает и для reaped-дедика** — Live показывает `gone`, История всё равно отдаёт строки (это acceptance-критерий фичи); деградация `logs_unconfigured`/`upstream` — мягкая подпись, как у metrics-`unconfigured`; **метрики** — 4 графика uPlot через metrics-proxy (`birdman_server_players|tick_ms`, `rate(birdman_container_cpu_seconds_total)`, `birdman_container_memory_bytes` по `server_id`), при ненастроенной (503) или недоступной (502) VM показывают «нет данных», а не падают.
- **Матч-дровер** (часть П1/П2, `components/MatchDrawer.tsx`): открывается кликом на строку матча в Live и Истории (`lib/drawer.tsx` — тот же провайдер, что и дедик-дровер, но `useMatchDrawer`). Метаданные из `GET /v1/matches/{id}` (переведённый бейдж состояния, длительность: finished — `ended_at−started_at`, live — тикающая от `started_at`); **статы** — 2 графика (`birdman_server_tick_ms`/`birdman_server_players` по `server_id`) через metrics-proxy за окно **[started_at, ended_at]** (finished — статично, не поллим; live — `[started_at, now]`, дозапрос — новый проп `range` у `<MetricChart>`); **логи** — переиспользован тот же `<LogsPanel>`, что и в дедик-дровере: Live (`<LogViewer initialFollow=false>` для finished) \| История (та же `serverHistoryQuery` по `server_id` матча).
