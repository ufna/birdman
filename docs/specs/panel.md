# Спека: админ-панель

> Первоклассный продукт, не приложение к API (`../03` §2): красивая админка мониторинга и статистики, главный скриншот OSS-анонса. Трек П0–П2 из `../05-runtime-iterations.md`.

## 1. Принципы

1. **Строго клиент публичного API**: OpenAPI + SSE (`/v1/events/stream`); если панели нужны данные — сначала эндпоинт, потом экран. Никаких приватных лазеек.
2. **Встраивается в master** (`go:embed` собранной статики): self-host получает панель бесплатно, «два бинаря + Postgres» остаётся правдой. Отдаётся с `/` того же listener'а :443.
3. Метрики-графики — из VictoriaMetrics **через master-proxy** (`GET /v1/metrics/query?...` → VM), чтобы панель не знала про топологию мониторинга.
4. Тёмная + светлая тема с первого экрана; live-обновления без F5 (SSE), таблицы переживают reconnect.
5. Auth: логин по admin API-ключу → HttpOnly session cookie; роли из скоупов ключа (readonly видит всё, кнопки скрыты).
6. **Интернационализация (уточнено в v0):** UI двуязычный — EN (каноничный, для OSS-анонса) + RU, **100% покрытие: ни одной захардкоженной user-facing строки** (правило держит guard-тест `no-hardcoded.test.ts`). Автоопределение при первом заходе (`navigator.languages` начинается с `ru` → RU, иначе **EN по умолчанию**), ручной выбор в `localStorage` переживает перезагрузку и больше не перебивается автоопределением. Бренд и API-токены (semver, id, сырые коды) не переводятся, но их **человекочитаемые подписи переводятся** — состояния (`state.*`), виды событий ленты (`event.*`, сырой код остаётся в `title` бейджа), скоупы ключа (`scope.*`).

## 2. Стек

React 18 + TypeScript + Vite; клиент API генерируется из `openapi.yaml` (`openapi-typescript`); графики — uPlot (лёгкий, real-time); таблицы — TanStack Table; стили — Tailwind + Radix-примитивы. Дизайн-токены (палитра/типографика) — отдельный файл, готовим к работе дизайнера (2–3 недели, до OSS-анонса обязательно).

(Уточнено в v0.) Клиент API пока написан руками и типизирован вручную (`panel/src/lib/api.ts` + SSE-подписчик `sse.ts` с реконнектом по `after_id`) — `openapi.yaml` ещё не существует; при его появлении клиент переводится на генерацию. Дизайн-токены — `panel/src/styles/tokens.css` (палитра из `docs/birdman-report.html`, обе темы). Сборка панели встраивается в master: `panel/build.sh` → `master/internal/panelui/static` (go:embed), node на хосте не обязателен (docker-фолбэк), без сборки master отдаёт placeholder.

(Уточнено в v0.) **i18n-слой** — свой лёгкий, без внешних либ: `panel/src/lib/i18n.tsx` (провайдер + хук `useT()` с `t(key, params?)` и plural-вариантом `tp(base, count)` на `Intl.PluralRules`; хук `useFormat()` — локале-зависимые длительность/относительное время/дата). Словари `panel/src/lib/locales/en.ts` (источник истины, `MessageKey = keyof typeof en`) и `ru.ts` (`Record<MessageKey, string>` — паритет ключей гарантируется компилятором + тестом: совпадение множеств ключей, отсутствие пустых значений, совпадение `{плейсхолдеров}`). **100% покрытие**: все пользовательские строки экранов/компонентов идут через `t()/tp()` — включая подписи состояний (`state.*`), видов событий ленты (`event.*` для всех kind из `store/*.go`; лента показывает подпись, сырой код — в `title`; неизвестный kind → сам код) и скоупов ключа (`scope.*`, показаны чипами в Shell). Единственный locale-слой вне каталога — `lib/format.ts` (единицы длительности/`… назад`, помечен `i18n-allow`). Технические `throw new Error(...)` вне провайдеров — по-английски (срабатывают до i18n). Формат чисел/дат/относительного времени локализован (`5s ago` / `5с назад`). Переключатель **EN/RU в Shell** рядом с темой/logout (компактный сегмент, `role=group` + `aria-pressed`). Дефолт EN, RU при `ru*`-локали; ручной выбор — `localStorage` (`birdman.lang`); ранний скрипт в `index.html` ставит `<html lang>` до первого рендера (без вспышки).

### П1 — операции (параллельно итерациям 4–5, ~2–3 недели) — ✅ реализовано (v0)

| Экран | Содержимое | Данные |
|---|---|---|
| **Дедик** (детали) | Стейт-таймлайн, метрики-графики (cpu/mem/net, tick_ms, players), **логи: live tail + скачать** (и для умерших) | `/v1/servers/{id}`, `/v1/servers/{id}/logs?follow=1`, metrics-proxy |
| **Матч** (детали) | Дровер: метаданные (состояние, регион, версия, длительность, пик игроков, начало/конец), **статы** (tick_ms + players за окно матча), **логи дедика матча** (+ скачать, и для reaped/failed) | `/v1/matches/{id}`, metrics-proxy `query_range`, `/v1/servers/{server_id}/logs` |
| **Деплои** | Таблица версий (semver, канал, состояние, дата), активная версия per регион, **прогресс pre-pull по тачкам**, кнопки Deploy / Rollback (с confirm), окно мультиверсий: сколько deprecated-дедиков ещё доигрывает | `/v1/versions`, `/v1/deploy`, `/v1/rollback`, SSE |
| **Действия с тачкой** | Drain / Undrain с прогрессом опустошения; причина карантина | `/v1/nodes/{id}/drain` |
| **События** | Полная лента events с фильтрами (kind, node, период) | `/v1/events` |

(Уточнено в v0.) Экраны **Деплои** (`/deploys`) и **События** (`/events`) добавлены в навигацию; детали дедика — дровер (Radix Dialog), открывается кликом на дедик во Флоте/Матчах и по ссылкам `srv …` в ленте. Всё — на существующем master API, новых эндпоинтов не добавляли.

- **Деплои**: таблица версий с цветными бейджами состояния (`toneOfVersionState`: registered/prepulling/active/deprecated/disabled); окно мультиверсий = active + deprecated и сколько дедиков каждой ещё живо (группировка `/v1/servers` по `version_id`, live-состояния); «активно по регионам» **выведено из живых дедиков** (`GET /v1/fleets` наружу не отдаётся — TODO в panel, per-region active_version недоступен точно); **прогресс pre-pull по тачкам** собран из событий `deploy_node_pulled` (множество спрогретых `node_id` + `remaining` из последнего события; total = спрогрето + remaining, либо оценка по живым нодам, пока событий нет), сидируется из `/v1/events` и обновляется по SSE (`deploy_started/node_pulled/activated/failed/rolled_back`); **Deploy/Rollback** — за confirm-диалогом Radix, `POST /v1/deploy` / `/v1/rollback`, кнопки скрыты у readonly-сессии (гейт `canDeploy` = скоуп deploy/admin из `GET /v1/session`).
- **Дедик-дровер**: отдельного `GET /v1/servers/{id}` в master нет → карточка ищет дедик в `/v1/servers` клиентом (логи/метрики работают и без строки, для reaped/failed); **таймлайн** — клиентский фильтр `/v1/events` по `server_id` (server-side фильтра нет — TODO) + live-дополнение из SSE; **логи** — live tail + скачивание файлом (`GET /v1/servers/{id}/logs?follow=&tail=`, chunked-стрим; download = тот же эндпоинт без follow → Blob); **метрики** — 4 графика uPlot через metrics-proxy (`birdman_server_players|tick_ms`, `rate(birdman_container_cpu_seconds_total)`, `birdman_container_memory_bytes` по `server_id`), при ненастроенной (503) или недоступной (502) VM показывают «нет данных», а не падают.
- **Матч-дровер** (часть П1/П2, `components/MatchDrawer.tsx`): открывается кликом на строку матча в Live и Истории (`lib/drawer.tsx` — тот же провайдер, что и дедик-дровер, но `useMatchDrawer`). Метаданные из `GET /v1/matches/{id}` (переведённый бейдж состояния, длительность: finished — `ended_at−started_at`, live — тикающая от `started_at`); **статы** — 2 графика (`birdman_server_tick_ms`/`birdman_server_players` по `server_id`) через metrics-proxy за окно **[started_at, ended_at]** (finished — статично, не поллим; live — `[started_at, now]`, дозапрос — новый проп `range` у `<MetricChart>`); **логи** — переиспользован `<LogViewer>` (`initialFollow=false` для finished). Живой матч рефетчится по SSE (`useData`), finished статичен. **Грациозная деградация**: `server_id === ''` (вычищен) → пустое состояние без запроса; пустая VM-matrix → «нет данных»; логи 404 (истекли/reaped) → статус `gone` в `lib/logs.ts` и подпись «Логи больше недоступны» — панель не падает и не крутит спиннер. Чистые хелперы окна/длительности — `lib/match.ts` (точки тестирования).
- **Действия с тачкой** (Флот): **Drain/Undrain** (`POST /v1/nodes/{id}/drain·/undrain`, confirm, admin-only) с индикацией опустошения (сколько allocated ещё доигрывает — из `/v1/servers`); причина карантина — из последнего события `node_quarantine` (client-фильтр ленты, т.к. фильтра по `node_id` у `/v1/events` нет).
- **События**: полная лента `/v1/events` с фильтрами kind/node/период и пагинацией — **клиентскими** поверх окна (у `/v1/events` только `limit`, нет `offset`/фильтров → TODO: серверные фильтры + keyset-пагинация), размер окна регулируется селектором; live-prepend через SSE (dedup по id).
- **Метрики-обёртка**: `lib/metrics.ts` (`parseMatrix` VM-matrix → серии для uPlot, `toAlignedData`, `queryRange` с мягкой деградацией) + переиспользуемый `<MetricChart query= title= unit= range?= />` (проп `range={start,end?}` — статичное окно истории матча без поллинга, либо живое `[start, now]` при `end` не заданном).
- Скоуп-гейт/CSRF/темы: деструктивные кнопки скрыты у readonly, показаны у deploy/admin; каждый не-GET несёт `X-Birdman-Csrf: 1`; обе темы; страница не скроллится по горизонтали до 1280px (таблицы/графики/логи скроллятся внутри контейнеров).
- Тесты (vitest, 88): парсер `parseMatrix`/`toAlignedData`/`formatMetric` + `queryRange` (503/502/ok), скоуп-гейт кнопок и `ConfirmButton`, reader лог-стрима (`pumpTextStream` + `streamServerLogs`, вкл. 404→`gone`); **i18n** — разрешение локали (`ru→ru`, `en→en`, дефолт `en`, порядок предпочтений, `localStorage`-override), паритет ключей en↔ru (+совпадение плейсхолдеров, подписи всех видов событий), интерполяция и plural (en/ru), бейдж события (подпись + сырой код в `title`, фолбэк на неизвестном); **guard `no-hardcoded.test.ts`** — скан `panel/src/**` на кириллические литералы вне `locales/`/`format`/тестов (комментарии вырезаются), ловит любую будущую захардкоженную строку; **матч-дровер** — маппинг длительности и окна метрик (`lib/match.ts`), пустые состояния логов/метрик (404/пустая matrix).

- **Графики** (`components/charts.tsx`): дневные агрегаты — стек-бары на DOM+SVG (без внешних зависимостей и canvas), с легендой, 2px-зазорами между сегментами и тултипом-разбивкой на колонку (Radix). uPlot в проекте рисует **линии** живых метрик (MetricChart); дневные столбики — другой визуальный язык, DOM-раскладка даёт корректные темы и отсутствие горизонтального скролла. **Категориальная палитра** серий (`--cat-1..8` в `tokens.css`, порядок blue→aqua→violet→orange→…) отделена от статусных цветов (good/warn/dead за состояниями) и провалидирована по CVD (dataviz): light ΔE ≥ 12, dark — floor-band со вторичным кодированием (легенда+подписи). Раскладка — чистые функции (`lib/stats.ts`: `toStackModel`/`toSimpleColumns`/`versionShareModel`/`utilizationModel`/`niceCeil`).
- **Статистика**: карточки (матчей за окно, пик CCU, средняя длительность, p50/p95 time-to-match); matches/players per day — стек по регионам; peak CCU и avg-duration per day — одиночные accent-ряды; распределение по версиям — горизонтальные доли (прямые подписи `версия · матчи · %`); fill-rate — p50/p95 + размер выборки + технический `source` (backend `note`/`source` — прокси allocation→match_start; истинное queue-wait — гистограмма `birdman_mm_time_to_match_seconds` через metrics-proxy, TODO).
- **Cost-view**: итог слото-часов; слото-часы/день **стек по регионам** и **стек по версиям**; утилизация тачек — метр `allocated/ready/draining/free` vs ёмкость активных нод (тона состояний, как во Флоте), явные единицы (slot-hours), UTC.
- **Алерты**: секции Активные / Правила / История (newest-first, лимит 20/50/100); severity → цветной бейдж (`toneOfSeverity`: critical→dead, warning→warn) через `StateBadge` с доменами `severity`/`alertstate`; read-only (mute/edit — TODO, это конфиг vmalert). **Описания алертов приходят с бэка как есть** (сейчас по-русски из vmalert) — показываем контент как пришёл, переводим только обвязку UI. Мягкая деградация (`lib/alerts.ts`): vmalert не настроен (503 `alerts_unconfigured`) / апстрим недоступен (502) — аккуратная подпись, а не падение (история из `alerts.log` работает независимо).
